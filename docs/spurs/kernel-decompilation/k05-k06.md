# DOA5U hot SPU kernels — reverse-engineered

Both kernels are two entry points of the **same skinning library** (see "Shared
infrastructure" at the bottom). They share: an index→matrix gather with a 144-byte
(`mpyui …,0x90`) bone-matrix record stride, a second 160-byte (`shli 5 + shli 7`)
per-influence stream stride, a self-modifying most-recently-used matrix-index cache
at LS 0x11790 / 0x11290, an alignment-checked fetch/DMA helper (`brsl 0x111e0` /
`0x10cd0`), and the Edge Newton-refined `frsqest` normalize.

The library is **Edge Geometry-derived but bespoke** (Team Ninja customised it —
see notes per kernel). This is classic per-frame SPU job code: DMA the vertex block
+ bone palette in, compute, DMA out.

---

## Kernel 6 — `spu_skin_vertex_positions`  (LS 0xe5f0, 1.73%, float 20%)

Matrix-palette **position skinning** with on-SPU **quaternion→matrix bone
decompression** and weighted blend, then transform.

### What it does (plain English)
- **DMA in:** a working vertex block (per-vertex position + up to N bone
  influences: index + weight), and a compressed bone palette (rotation quaternion
  + translation per bone), streamed/cached on demand.
- **Compute:** for each vertex, walk its influence list. For each influence: fetch
  the bone by index (144-byte record, DMA'd if not already in the LRU cache),
  decode its quaternion into a 3x3 rotation matrix on the fly, weight-blend the
  bone transforms, and transform the vertex position. A trailing
  squared-length / `fcgt` test updates a per-batch bound (bounding-sphere or
  cull accumulator).
- **DMA out:** skinned positions back to the vertex block.

### Reconstruction
```cpp
// --- quaternion -> rotation matrix (0e5f0..0e638) ---
// r68 = 2.0f, r4 = 1.0f. q = (x,y,z,w) splatted per lane.
mat3 quat_to_matrix(vec4 q) {
    float xx=q.x*q.x, yy=q.y*q.y, zz=q.z*q.z;   // fm r32/r33 + zz
    float xy=q.y*q.x, zw=q.z*q.w;               // fm r107, r98
    mat3 m;
    m[0][0] = 1 - 2*yy - 2*xx;   // fnms r77  (1 - 2y² then -2x²)
    m[0][1] = 2*xy - 2*zw;       // fnms r12
    m[1][0] = 2*xy + 2*zw;       // fma  r79
    // ... remaining rows built by the same 1-2(..) / 2(..±..) pattern,
    //     repacked into rows by the shufb r75/r73/r74 group.
    return m;
}

// --- weighted blend accumulate (0e648..0e658) ---
// r72 = influence weight, lerp toward the bone-transformed value
acc = acc + weight * (transformed - acc);      // fs + fma

// --- matrix * vertex (0eaa0..0eb08, and the fma cascade 0eab4..0eb40) ---
vec3 skin_position(vec3 v, const BoneXform bones[], const Influence infl[], int n) {
    vec3 pos = 0;
    for (int i = 0; i < n; ++i) {
        const Bone& b = fetch_bone(infl[i].index);   // 144B record, cached/DMA
        mat3  R  = quat_to_matrix(b.rot);
        vec3  p  = R * v + b.translation;             // fm + fma cascade
        pos = pos + infl[i].weight * p;               // weighted blend
    }
    // bound / cull accumulator (0eb40..0eb68)
    float d2 = dot(pos, pos);
    if (d2 > bound) update_bound(pos);                // fcgt r35 + selb/shufb
    return pos;
}
```

### Confidence & ambiguities
- **High** that this is matrix-palette skinning of positions with quaternion bone
  decode + weighted blend. The `1-2(y²+z²)` / `2(xy±zw)` pattern is unmistakably
  quaternion→matrix; the `pos += w*(bone*v)` cascade is unmistakably skinning.
- **Medium** on exact field offsets (bone stride 144B, influence stride 160B are
  read from the code but the sub-field layout is inferred).
- The trailing `fa`/`fm`/`fcgt` block (0eb40+) is either a bounding-volume update
  or a degenerate-triangle/`w`-clamp; I lean bounding-sphere accumulation.
- Calls a bigger helper at `0xb538` (likely the influence-list walker / DMA list
  builder) not contained in this window.

## Kernel 5 — `spu_skin_tangent_frame`  (LS 0xf54c, 2.10%, float 15% shuffle 22%)

Skinning + **re-normalization** of the per-vertex **tangent basis** (normal /
tangent / binormal), i.e. the normal-mapping companion pass to kernel 6.

### What it does (plain English)
- **DMA in:** the same working vertex block (now the TBN vectors + influence
  list) and the bone palette (on-demand GET, `MFC_Cmd GET`, 32-byte fetches at
  the tail).
- **Compute:** skin the normal, tangent and binormal by the same weighted bone
  palette, then **renormalize each** with a Newton-refined `rsqrt` (with a
  zero-length guard), and **re-orthogonalize** the frame with a Gram-Schmidt /
  cross-product step so it stays orthonormal after blending. A final tight loop
  applies a per-component **output scale** and writes back.
- **DMA out:** the corrected TBN frame.

### Reconstruction
```cpp
// --- Edge Newton-refined normalize (0f74c..0f788; repeated 0f9d8/0faa0/0fb30) ---
// r28 = 0.5f, r18 ≈ 1.0f (0x3f800001). Guards zero length via fcgt vs epsilon.
vec3 normalize_safe(vec3 v) {
    float d  = dot(v, v);                 // fm + fma + fma  (x²+y²+z²)
    float y  = frsqest(d);                // 1/sqrt estimate
    y = fi(d, y);                         // SPU refine
    y = y + (1.0f - d*y*y) * (0.5f*y);    // fnms + fma  (Newton step)
    vec3 n = v * y;
    return (d > EPS) ? n : v;             // selb zero-length guard
}

// --- one cross/Gram-Schmidt component (0fa5c..0fa78, 0fb00..) ---
// a*b - c*d form => cross product / orthogonalization determinant
t = t - dot(t, n) * n;                    // remove normal component from tangent
b = cross(n, t);                          // rebuild binormal

// --- overall pass ---
void skin_tangent_frame(Vertex& v, const BoneXform bones[], const Influence infl[], int n) {
    vec3 N = skin_vector(v.normal,   bones, infl, n);   // blend, no translation
    vec3 T = skin_vector(v.tangent,  bones, infl, n);
    N = normalize_safe(N);
    T = normalize_safe(T - dot(T,N)*N);                 // Gram-Schmidt
    vec3 B = normalize_safe(cross(N, T));               // (handedness from v.w)
    v.normal = N; v.tangent = T; v.binormal = B;
}

// --- hot tail: per-component output scale (0f54c..0f594, stride 0xA0=160) ---
// r77, r13 = scale constants; extract scalar, scale, reinsert, store.
for (each out vertex, stride 160) {
    field_a *= r77;                       // rotqby + fm + shufb + store
    field_b *= r77;
    field_c *= r13;                       // 0x70(base): different scale
}
```

### Confidence & ambiguities
- **High** that this is a normalize/orthonormalize pass on skinned basis vectors:
  three back-to-back `frsqest` normalizes + `a*b−c*d` cross/projection + `selb`
  zero-length guards is the textbook TBN-fixup after skin blending.
- **Medium** on whether all three of N/T/B are skinned here vs. loaded already
  skinned; the vector-skin blend shares code with kernel 6, so I show it skinned.
- The hot sampled PC (0xf54c) is the **tail scale loop**, which is why shuffle is
  high (22%) — it is scalar-extract/reinsert bound (`rotqby`+`shufb` per field),
  not float bound. That loop is the per-frame throughput cost; the normalize/
  orthogonalize block above it is the algorithmic body.
- `r77`/`r13` output scales are most likely a fixed-point requantize or a
  model/units scale applied on the way out.

## Shared infrastructure (both kernels — the "stock EDGE vs bespoke" answer)

- **Indexed matrix streaming w/ LRU cache:** `mpyui idx,0x90` gathers 144-byte
  bone records; a self-modifying tag table at LS 0x11790 (k5) / 0x11290 (k6) plus
  companion 0x117a0 / 0x112a0 records the most-recently-fetched index so repeated
  bones skip the fetch. The `shufb #i8[0]` → `stqr` back into the table is
  **Edge-style branch-hint / cache-tag self-patching**.
- **Alignment-checked fetch helper** `brsl 0x111e0` / `0x10cd0`: computes
  `andi …,0xf` 16-byte-alignment masks and `heqi lr,…,0` asserts before fetching
  — the matrix-get / DMA-list path.
- **On-demand DMA:** kernel 5's tail issues an explicit `MFC GET` (32B, tag wait
  via `MFC_RdTagStat`) — the bone-palette-on-demand streaming Edge is known for.
- **Verdict:** the skeleton (indexed skinning, matrix cache, self-patching hints,
  Newton `frsqest` normalize, 0x90 command stride) is **Edge Geometry**. But the
  quaternion-decompressed bone palette (kernel 6 decodes quats to matrices on the
  SPU rather than consuming pre-built matrices) and the fused TBN-orthonormalize
  pass (kernel 5) are **bespoke Team-Ninja extensions** — stock Edge Geom skins
  from a matrix palette and does not decode quaternions inline. So: **Edge-derived
  runtime, customised animation/skinning front-end.**
