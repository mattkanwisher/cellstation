# DOA5U hot SPU kernels — reverse engineering (result_B)

Two 576-instruction disassembly windows centered on the hottest PCs. Neither
window is a single self-contained "DMA-in / compute / DMA-out" loop; each is a
slice of a larger SPU program. I reconstruct the algorithm each hot region
implements, not every register op.

---

## k03 — LS 0x5498, hash VqbXrQEQ80i (2.83%, 0% float, shuffle-heavy)

### Verdict up front
The prompt's guess ("vertex DECOMPRESSION / data reshaping") does **not** hold.
There is no bit-unpack of packed 11/10/16-bit vertex fields and no `cuflt`/scale
anywhere. What this window actually contains is the **SPU job runtime / command
dispatcher + coroutine context switch + scratch-pool initializer**. The heavy
shuffling is struct field marshaling (unaligned scalar insert/extract via
`cwd/cdd/chd`+`shufb`), not numeric decompression. This is the "marshaling" leg
of the "geometry/skinning/marshaling" trio, i.e. the driver that feeds the math
kernels — it is hot because every job passes through it.

### What the window is made of (four distinct regions)

1. **Function prologue/epilogue + control-block housekeeping** (0x5498–0x55f4).
   Tests lanes of a state word (`lqd r106,0xf10(r81)`; `shlqbyi …,4/,8`+`ceqi 0`),
   zeroes fields of a control block at `r81+0xAC0`, then `brsl 0xaa0`. The tail
   (0x55cc–0x55f4) is a textbook callee epilogue: `lqd lr,0xa0(sp)`, `ai sp,sp,0x90`,
   reload callee-saved `r80..r86`, `bi lr`. So `r81` is the persistent job context
   and `sp+…` is a normal C stack frame — this is compiled C, not hand ISA.

2. **Command / display-list dispatch loop** (0x553c–0x55b4). Per item it reads
   four **byte** fields at record offsets 0x15/0x16/0x17/0x1a using the canonical
   "unaligned scalar" idiom (`lqx` aligned quad + `rotqby` by the address low
   bits), advances the record pointer by 8 (`ai r80,r80,8`), bumps an item counter
   (`ai r81,r81,1`), then uses the opcode byte to index a handler table
   (`andi …,0xff` → `a r10,r85,byte` → `brsl 0x5400`). Classic opcode-stream
   interpreter: read type tag, jump to per-command handler.

3. **Full-context coroutine / fiber switch** (0x5898–0x5a24). Saves the entire
   register window `r81..r127` to `[r6 + 0x40 + 16*i]`, then loads a *new* context
   — `lr, sp, r2, r80..r121` — from `[r5 + …]`. Save-one-context / restore-another
   is a stackful coroutine (SPURS-task / fiber) switch, not a leaf call. After it,
   0x5a28–0x5adc is high-level orchestration: a run of `brsl` to eight subsystems
   (0x6740, 0x10db0, 0x79f0, 0x6e88, 0xa028, 0x6fe0, 0x7188, 0x6350, 0x54e0) with
   argument shuffling — the job's main driver.

4. **Scratch-pool / free-list initializer** (0x5ae0–0x5d94). Masks a 29-bit size
   (`& 0x1fffffff`), rounds it up to a multiple of 0x80 (`+0x7f & ~0x7f`), computes
   the padding, then runs several fill loops (counts 0x7ff etc.) that write
   incrementing self-referential entries `{0xff000000 | (base + i*0x100)}` into a
   table — i.e. it lays out a linked free-list / block table over a memory region.
   `shufb` here is only aligned/unaligned word insertion into the table.

### Readable C++ reconstruction

```cpp
// Persistent per-job context lives at r81; r5/r6 are saved/restored fiber frames.
struct JobContext {                 // r81
    /* … */
    u8   status_flags;              // +0xF10 region, lane-tested on entry
    CtrlBlock ctrl;                 // +0xAC0  (zeroed / reset here)
    /* … */
};

// (1) entry: validate state, reset control block, call setup
i32 spu_job_run(JobContext* ctx) {
    if (ctx == nullptr) return /*…*/;                 // brz r3
    if (state_lanes_nonzero(ctx->status_flags))       // shlqbyi+ceqi+nor+or
        goto error_path;                              // brnz 0x19b8
    reset_ctrl_block(&ctx->ctrl);                     // zero fields at +0xAC0
    setup(&ctx->ctrl, /*mode=*/2);                    // brsl 0xaa0

    // (2) walk the command/token stream, dispatch by opcode byte
    for (Item* it = stream; /*cond*/; it = it->next /* +8 */, ++count) {
        u8 op   = it->bytes[0x15];                    // opcode / type tag
        u8 a    = it->bytes[0x16];
        u8 b    = it->bytes[0x17];
        u8 c    = it->bytes[0x1a];
        Handler h = handler_table[op];                // r85[op]
        h(ctx, a, b, c);                              // brsl 0x5400
        if (done(...)) break;                         // brhz 0x2134
    }
    // … epilogue: restore r80..r86, return
}

// (3) cooperative task switch (stackful fiber)
void context_switch(Frame* save_to /*r6*/, Frame* load_from /*r5*/) {
    for (int r = 81; r <= 127; ++r) save_to->gpr[r] = REG(r);   // stqd r81..r127
    LR = load_from->lr;  SP = load_from->sp;                    // lqd 0x00/0x10
    for (int r = 80; r <= 121; ++r) REG(r) = load_from->gpr[r]; // lqd 0x30..
    // drivers: geom(), skin(), dma(), … 8 subsystem calls follow
}

// (4) build a free-list / block table over a scratch region
void pool_init(u8* base, u32 size) {
    size = (size & 0x1FFFFFFF);
    u32 padded = (size + 0x7F) & ~0x7Fu;              // round to 128
    u32 npad   = (padded - size) >> 1;
    for (u32* e = table, ptr = start; count-- ; ++e, ptr += 0x100)
        *e = 0xFF000000u | ptr;                       // tagged next-pointer
}
```

### Plain English
Receives a job (DMA'd descriptor referenced through `r81`), validates/reset its
control block, interprets a command stream one token at a time dispatching each
opcode byte to a handler table, can suspend/resume via a full stackful fiber
switch, drives the geometry/skinning/DMA subsystems, and initializes a
scratch-memory free-list. Pure control-flow + pointer/struct marshaling — hence
0% float and shuffle-heavy.

### Name
`spu_job_dispatch` (a.k.a. `spu_cmdstream_interp_and_taskswitch`). If a single
descriptive symbol is wanted for the whole window: **`spu_job_runtime_dispatch`**.

### Confidence & ambiguities
- Med-high that this is a job/command runtime, not a compute kernel — the
  epilogue, opcode-table dispatch, full-context save/restore, and free-list build
  are individually unambiguous idioms.
- The scratch-init loops could be a heap free-list, a DMA-list builder, or an
  index-remap table; I can't disambiguate from the window alone (the `0x100`
  stride and `0xff000000` tag fit a tagged free-list best).
- The command stride is 8 bytes but fields read at 0x15–0x1a, so items are larger
  than 8B or the pointer indexes a header array — exact record layout unresolved.

### Stock EDGE vs bespoke
Bespoke. The stackful fiber switch + opcode interpreter looks like a
SPURS-taskset job runtime or Team Ninja's own SPU task kernel, **not** stock
`edgeGeom`. Stock EDGE geometry has no coroutine context switch like this.

## k04 — LS 0x9438, hash JGKH1bLcWfR (2.64%, shuffle 29%)

### Verdict up front
This one **is** a geometry math kernel: a **flag-driven per-vertex transform /
lighting-setup / projection** stage. Per vertex it assembles xyz from a strided
input stream, transforms it by constant-pool matrices, transforms+normalizes the
normal (rsqrt Newton refine), does a perspective reciprocal (`frest` 1/w), and
scatters the repacked result into several output vertex buffers. This is the
"geometry reshaping" the prompt expected.

### Evidence
- **Input gather (0x9438–0x9478):** three scalars fetched from source `r85` at
  strided offsets and inserted into lanes `#i32[0..2]` of `0x140(r81)` — building
  an AoS `{x,y,z}` from a de-interleaved/strided vertex stream.
- **Constant matrix pool via `lqr`:** rows at `0xBD90–0xBDC0`, `0xBE50–0xBE80`,
  and `0xBC20–0xBC60`(+`0xBC80–0xBCA0`) — at least three 4×4 matrices held in LS.
- **Matrix×vector (0x9504–0x9594, 0x9604–0x9670):** splat each vector lane
  (`shufb …,r48,r98/r113/r99`) then `fm`+`fma`+`fma` dot chains, `selb` to keep w,
  `stqd …,0x50(r21)`. Standard 4-row transform of a point.
- **Vector subtract / edge build (0x9678–0x96f0):** `fs r53,fs r25,fs r51` build a
  component-wise difference, repacked and `fa`-accumulated → e.g. `v1 - v0`.
- **3×3 transform of normal (0x9728–0x9794):** matrix `0xBE50`, three-term
  `fm/fma/fma` (no translation lane), store `0x40(r81)`.
- **Cross product + normalize (0x97a8–0x98bc):** interleaved `fm/fma/fnms`
  (`a*b − c*d`) cross-product pattern, then dot(v,v) via `fm`+`fma`+lane-sum,
  `frsqest`→`fi`→`fma` (rsqrt + one Newton step), `fm` to scale — a unit normal
  (or tangent-frame) computation.
- **Perspective / projection (0x98c0–0x9b04, 0x9b08–0x9d34):** matrix `0xBC20`,
  `frest r69,r4`+`fi r66,r4,r69` = refined reciprocal of w for three lanes,
  `fm …,(1/w)` = perspective divide, then a long `fma` transform + dense `shufb`
  repack and `stqx` scatter.
- **Flag-driven paths:** `0xb0(r81)` byte tag repeatedly loaded, `rotqbyi …,0xd`
  + `ceqbi 0` + `brnz`, selects which of the above paths runs per vertex.
- **Fan-out stores:** the same transformed result (`r75/r77/r78`) is written to
  many strided offsets (`0x190/0x790/0xd10/0xdd0/…(sp)`) — output goes to several
  vertex buffers (multi-pass / strip expansion / shadow+main).

### Readable C++ reconstruction

```cpp
struct VtxWork {                  // r81 scratch context
    vec4 in_xyz;                  // +0x140 assembled from strided source
    vec4 pos;                     // +0x30 accumulator
    vec4 nrm;                     // +0x40
    vec4 out;                     // +0x50
    u8   flags;                   // +0xb0 (tag at +0xd), selects path
    // …
};

// constant-pool matrices (loaded by lqr)
mat4 M_pos   = load(0xBD90);      // object/world → view
mat4 M_nrm   = load(0xBE50);      // 3x3 normal rotation
mat4 M_proj  = load(0xBC20);      // view → clip/screen

for (each vertex v) {
    vec4 p = gather_xyz(src, v);              // 0x9438: strided → AoS

    // position transform (4-row dot products)
    vec4 c = M_pos * p;                       // fm+fma+fma, selb keeps w
    w.pos = c;

    // edge / delta (v_i - v_j) used downstream
    vec4 e = sub_pack(a, b) + base;           // fs/fs/fs + fa

    // normal: 3x3 transform, then cross + normalize
    vec3 n = M_nrm * v.nrm;                   // 3-term fma
    vec3 t = cross_terms(...);                // fnms/fma cross pattern
    float inv = rsqrt_refine(dot(t,t));       // frsqest→fi→fma
    n = t * inv;                              // unit normal/tangent

    // projection: perspective divide by w, then clip matrix
    vec3 rw = frest_refine(c.w_lanes);        // frest→fi  (1/w)
    vec4 clip = M_proj * (c * rw);            // fm(1/w)+fma chain

    // repack and scatter to several output vertex streams
    OutVtx o = pack(clip, n, ...);            // dense shufb
    for (buf in out_buffers) buf[v] = o;      // fan-out stqd/stqx
}
```

### Plain English
A per-vertex T&L/geometry stage. DMA'd inputs: a strided source vertex stream
(positions/normals) and a small constant matrix pool (view, normal, and
projection matrices in LS). Per vertex it assembles the position, transforms it,
transforms and renormalizes the normal (and builds a cross-product frame),
applies the perspective reciprocal and projection matrix, then writes the packed
transformed vertex into several output buffers. Output: transformed/projected
vertices ready for the rasterizer/RSX. Float-heavy with ~29% shuffle because
every transformed value is (de)interleaved between AoS and lane-splat form.

### Name
`spu_vertex_transform_project` (fuller: **`spu_geom_transform_normal_project`** —
position transform + normal transform/normalize + perspective projection +
output repack).

### Confidence & ambiguities
- High that this is per-vertex transform + normalize + projection: the matrix-row
  dot chains, `frsqest/fi` normalize, and `frest/fi` reciprocal-of-w are
  unmistakable.
- Whether the cross-product block produces a face normal, a tangent, or a
  light/half-vector is ambiguous from the window; I call it "normal/tangent
  frame."
- The multi-buffer fan-out could be strip expansion, LOD duplication, or a
  shadow+main double write — not decidable here.
- Exact roles of the three matrices (which is world vs view vs proj) are inferred
  from usage order, not proven.

### Stock EDGE vs bespoke
Strongly EDGE-Geom-shaped (constant matrix pool + transform + `frest` projective
divide + AoS↔SoA repack is exactly the `edgeGeom` transform/output idiom).
Likely stock `edgeGeom` or a light Team-Ninja derivative; less bespoke than k03.

## 3–4 line summaries

**k03 (`spu_job_runtime_dispatch`)** — Not decompression. It is the SPU job
runtime: validate/reset a job control block, interpret a command stream by
dispatching each opcode byte through a handler table, switch stackful
fiber contexts (save r81–r127 / load a new frame), drive 8 subsystems, and
lay out a scratch free-list. 0% float because it's all pointer/struct
marshaling. Bespoke (SPURS-task / Team-Ninja kernel), not stock EDGE.

**k04 (`spu_vertex_transform_project`)** — A per-vertex T&L kernel. Assembles xyz
from a strided source, transforms by constant-pool matrices, transforms and
renormalizes normals (rsqrt Newton refine + cross product), does the perspective
reciprocal (frest 1/w) and projection, and scatters repacked vertices to several
output buffers. Flag byte at 0xb0(r81) selects the path per vertex. Strongly
EDGE-Geom-shaped, likely stock/near-stock `edgeGeom`.
