# DOA5U hot SPU kernels — reverse engineering

Both inputs are fixed 576-line **windows** into larger SPU jobs, not complete functions
(k01 branches back to `0xc6d8`, before the window; k02 runs off the end mid-instruction).
So the disassembly is a representative slice, and structure/purpose is inferred from the
idioms present, not from a full entry-to-`bi lr` trace.

**Cross-kernel fact (high confidence):** k01 and k02 share a byte-identical *guarded vector
normalize* idiom — same magic constants loaded from LS `0x10f50`, same Newton-Raphson rsqrt
refinement (`frsqest`→`fi`→`fm`/`fnms`/`fma`), and the same "degenerate-length" diagnostic
latch that stores a `1` byte to globals `0x11290`/`0x112a0`. They are compiled from the same
in-house math/geometry library. That diagnostic latch (a once-only "bad vector encountered"
flag, gated by an `fcgt` epsilon test and `heqi lr`/`heq` asserts elsewhere) is the signature
of **debug-instrumented bespoke engine code**, not stock middleware.

## Kernel 1 — `k01_0cf24` (3.07%, hottest)

### What it demonstrably does
A large, branchy **top-level SPU job** (0x8c80 = ~36 KB stack frame, restores r80–r126 in the
epilogue at `0d3e8`) that loops over elements and mixes three recognizable primitives with a
data-structure traversal:

1. **Guarded vector normalize** (3× in the window: `0cf24`, `0cfa8`, `0d224`) — squared length
   via `fma` accumulation, `frsqest` + one Newton step, `selb`-guarded against near-zero.
2. **Full 4×4 matrix × vec4 point transform** (`0d040`–`0d09c`): four consecutive `lqd` from a
   64-byte matrix = rows 0..3; input vector gets `w=1` forced in (`shufb #i32[3]`), each lane is
   splatted with a constant `shufb` pattern (`0x00010203`, `0x04050607`, `0x08090a0b`,
   `0x0c0d0e0f`), then `out = x·row0 + y·row1 + z·row2 + w·row3`. Afterward the original `w` is
   shuffled back in — a **position** transform.
3. **A small-integer type dispatch** (`0d0bc`: `clgti r,·,3` / `clgti r,·,2` → branch): a switch
   on a component/attribute code in 0..3, i.e. a per-attribute or per-format code path.
4. **Indexed traversal** of arrays of **144-byte (0x90) records** (`mpyui …,0x90`), extracting
   scalar fields with `rotqby`, chasing offsets, calling helpers via `brsl` (`0x11640`,
   `0x10cd0`, `0x111e0`) with `heqi lr` bounds asserts.
5. **Inter-record distance + threshold branch** (`0d224`–`0d260`): `d = pB.xyz - pA.xyz` (both at
   offset `0x70` in their 144-byte structs), `rsqrt(|d|²)`, compare against a threshold and
   branch — a proximity / LOD / culling test.
6. **A reciprocal-driven positional correction** at the tail (`0d7f8`–`0d820`): `frest`+`fi`
   (= 1/x), then an `fma` chain `(b−a)·(1/·)…` written back to `0x40(r8)`.

### Reconstruction (structure + algorithm)
```cpp
struct Node {          // 144-byte (0x90) record — joint/bone-like
    /* 0x00.. */ ...;
    float3 pos70;      // at 0x70, used for inter-node distance
    /* ... */
};

// vec3 normalize with the shared guarded rsqrt (both kernels)
inline float3 normalize_guarded(float3 v) {
    float  l2 = dot(v, v);
    float  r  = frsqest(l2);
    r = r * (1.5f - 0.5f * l2 * r * r);      // one Newton step (fi/fm/fnms/fma)
    if (l2 <= EPS) { latch_degenerate_flag(); return v; }  // stores 1 -> LS 0x11290
    return v * r;
}

void spu_job(Ctx* c) {                       // ~36KB frame, saves r80..r126
    for (each element) {
        n0 = normalize_guarded(vecA);        // normals / tangents / bone axes
        n1 = normalize_guarded(vecB);
        float4 p = mat4_transform_point(M, in.xyz);   // x·r0+y·r1+z·r2+w·r3, w restored

        switch (attr_type /* 0..3 */) { ... }         // per-attribute/format path

        // traverse index/adjacency list of 144-byte Nodes
        for (Node* a, *b : indexed_pairs) {
            float3 d  = b->pos70 - a->pos70;
            if (rsqrt(dot(d,d)) > threshold)  goto handle_close;   // proximity test
        }
        // tail: reciprocal-based correction (constraint / interpolation)
        float3 delta = b - a;
        float  inv   = 1.0f / len_or_w(delta);         // frest + refine
        out[0x40]    = fma_chain(delta, inv, ...);     // positional correction
    }
}
```

### Plain English
Streams over an array of ~144-byte joint/segment records, **transforms positions by a 4×4
matrix**, **normalizes** associated direction vectors, **dispatches on an attribute/format code**,
walks an **index/adjacency structure** doing **inter-joint distance tests**, and finishes with a
**reciprocal-based positional correction**. The distance-test-then-correct shape (normalize a
delta, `1/d`, nudge a position) is the classic form of a **distance/contact constraint** — i.e.
this reads as a **skeletal physics / collision-constraint solve** (DOA5U's soft-body/jiggle and
bone-collision are exactly this kind of per-frame SPU work), wrapped around ordinary
transform+normalize geometry prep.

### Name
`spu_skeletal_transform_and_constraint_solve`
(alt, if you prefer neutral: `spu_geom_transform_normalize_traverse`)

### Confidence
- Individual idioms (normalize, 4×4 point transform, 144-byte indexed traversal, distance test,
  reciprocal correction, big-frame job entry): **high**.
- Overall "physics/collision constraint" label: **medium** — the traversal + distance + correct
  pattern strongly implies constraint solving, but the window omits the head of the loop and the
  helper subroutines, so it could also be a proximity-weighted skinning/deform pass. The
  attribute-type `switch` and what exactly gets corrected are **ambiguous**.

### EDGE vs bespoke
**Bespoke game/engine code.** The `heqi/heq lr` asserts, the once-only "degenerate vector"
diagnostic latch to fixed globals, the 144-byte joint records, and the branchy adjacency
traversal are not the shape of stock Sony **EDGE Geometry** (which is a tight, mostly
branch-free SoA decompress→skin→compress pipeline). Some primitives (4×4 transform, rsqrt
normalize) are generic and could sit on EDGE-style helpers, but the job as a whole is in-house.

## Kernel 2 — `k02_0a538` (2.99%, float-SIMD heavy)

### What it demonstrably does
A **matrix/animation math** job, denser in float SIMD than k01:

1. **4×4 × 4×4 matrix multiply / concatenation** (`0a5b0`–`0a634`): rows of matrix A (`lqd` at
   `0(r24)`,`0x10`,`0x20`,`0x30`) times rows/cols of matrix B, each output row =
   `Σ splat(A.lane)·B.row` via `fm`/`fma`, then `fa` to combine. Composes a bone matrix (with a
   parent or with the view/model matrix).
2. **Branchless matrix → quaternion** (`0a644`–`0a76c`): the textbook max-diagonal method —
   `fcgt` compares the three diagonal terms (`0a668`,`0a698`,`0a6b0`) and `and`s the results to
   pick the largest component; `fs`/`fa` build the trace-based sums and the off-diagonal
   *differences* `(m_ij − m_ji)`; `s = 0.5 / sqrt(diag_term)` is formed with `frsqest` + Newton
   refine + `fm ·0.5`; the differences are splatted and multiplied by `s` to yield the quaternion
   components. (Constants `0x3f800001`, `0.5f`, and the select/shuffle patterns loaded from
   `0x10f30`–`0x11080` are the per-case masks.)
3. **A quantize/pack loop** (`0a770`–`0aa00`, back-edge `brnz r86,0xa7b8`): indexed `lqx` gathers,
   **dequantize** via six `fma` with a shared scale `r35` and bias `r34` (`v = raw·scale+bias`),
   **requantize** via `cflts …,0xad` (float→fixed-point int at a fixed scale), `ceq` comparisons
   + `gb` (gather-bits) to build change/selection masks, then a **bump-allocate** (`0aa04`–`0aa38`:
   size add, `ai …,0xf`/`andi …,-0x10` 16-byte align, pointer bumped at `0x190(r81)`, `brsl 0x5f20`)
   that appends packed 16-bit values (`shufb #i16[0]`, `stqd`) to an output stream.
4. **Repeated orthonormal-frame construction from joint positions** (`0aa58` onward, unrolled
   many times through the end of the window): load two vec3s at offset `0x40` of 144-byte
   (`mpyui 0x90`) / 160-byte (`mpyui 0xa0`) bone records, subtract, **normalize** (the shared
   guarded rsqrt), then `fm`+`fnms` = Gram-Schmidt projection-subtraction to build a perpendicular
   axis. This is per-joint **aim/twist basis** construction.

### Reconstruction (structure + algorithm)
```cpp
struct Bone { /* 144 (0x90) or 160 (0xa0) bytes */
    float4x4 mtx;      // rows at 0x00/0x10/0x20/0x30
    float3   pos40;    // at 0x40, used for frame building
    ...
};

quat mat3_to_quat(const float3x3& m) {           // branchless max-diagonal
    // pick largest of {trace, m00, m11, m22} with fcgt+and, form (m_ij - m_ji),
    float s = 0.5f * rsqrt_refined(diag_term);    // frsqest -> fi -> fm/fnms/fma -> *0.5
    return build_quat(diffs * s);
}

void spu_job(Ctx* c) {
    float4x4 M = matmul4x4(A, B);                 // concatenate matrices
    quat     q = mat3_to_quat(M.rot());           // matrix -> quaternion

    // pack loop: dequantize (v = raw*scale + bias) -> requantize (cflts) -> bitmask (gb)
    //            -> 16-byte-aligned bump-allocate -> emit packed 16-bit stream
    for (each element) {
        float6 v = raw * scale /*r35*/ + bias /*r34*/;
        int16  q[] = cflts(v, /*scale*/0xad);
        mask       = gather_bits(compare(q, prev));
        emit_packed(out, q, mask);               // stqd 16-bit, ptr@0x190 bumped, brsl 0x5f20
    }

    // build per-joint orthonormal frames from position deltas
    for (each bone pair) {
        float3 aim = normalize_guarded(boneB.pos40 - boneA.pos40);
        float3 up  = normalize_guarded(orthogonalize(ref, aim)); // fm + fnms (Gram-Schmidt)
        // ... third axis
    }
}
```

### Plain English
DMAs in bone matrices, **concatenates matrices**, converts a rotation matrix **to a quaternion**
(branchless largest-diagonal method), and runs a **dequantize→requantize→pack loop** that
gathers indexed float attributes, rescales them (`v = raw·scale + bias`), quantizes to
fixed-point (`cflts`), builds change-masks with `gb`, and appends a compressed **16-bit packed
stream** through a 16-byte-aligned bump allocator. It also builds **orthonormal bone frames**
(aim + Gram-Schmidt perpendicular) from inter-joint position deltas. Net: a **skeletal pose
build + pose/attribute compression** job — matrix palette assembly, quaternion conversion, and
quantized output — adjacent to but broader than plain vertex skinning.

### Name
`spu_pose_build_matrix_to_quat_quantize`
(alt: `spu_bone_palette_compose_and_pack`)

### Confidence
- 4×4 matrix multiply, matrix→quaternion (max-diagonal + `s=0.5/sqrt`), `cflts` quantization,
  `gb` mask-pack, bump-allocated 16-bit output, and Gram-Schmidt frame build: **high**.
- Overall "pose build + pose compression" purpose: **medium**. It's clearly matrix/quaternion +
  quantized packing, but whether the packed stream is a compressed animation pose, a bone-matrix
  palette for the GPU, or requantized vertex attributes is **ambiguous** from the window (the
  DMA-out and the meaning of the 0xad quantization scale aren't in view). The hint "likely
  skinning" is directionally right but this is the *setup/compression* side, not the per-vertex
  blend.

### EDGE vs bespoke
**Bespoke**, though closer to EDGE-flavored primitives than k01. The dequantize/requantize +
indexed-gather + 16-bit packing loop resembles EDGE's fixed-point vertex (de)compression, and if
any stock code is reused it would be here. But the matrix→quaternion conversion, the bump
allocator writing an application-defined stream, and the shared in-house guarded-normalize +
diagnostic latch mark it as game/engine code, not stock EDGE Geometry as shipped.

## 3–4 line summaries

**k01 — `spu_skeletal_transform_and_constraint_solve`**
Big top-level SPU job over ~144-byte joint records: 4×4 point transforms + guarded vector
normalizes, an attribute-type switch, index/adjacency traversal with inter-joint distance tests,
and a reciprocal-based positional correction — reads as skeletal physics/collision-constraint
solving wrapped around geometry prep. Idioms high-confidence; "physics" label medium. Bespoke
engine code (asserts + diagnostic latch), not stock EDGE.

**k02 — `spu_pose_build_matrix_to_quat_quantize`**
Float-heavy animation-math job: 4×4 matrix concatenation, branchless matrix→quaternion (max-
diagonal, `s=0.5/√trace`), a dequantize→`cflts`-requantize→`gb`-mask→bump-allocated 16-bit pack
loop, and Gram-Schmidt orthonormal bone-frame construction from joint deltas. Core idioms high-
confidence; exact output (compressed pose vs GPU bone palette vs requantized attributes) medium.
Bespoke, with EDGE-style (de)quantization primitives.

Both kernels are compiled from the **same in-house math/geometry library** (identical guarded-
normalize + degenerate-vector diagnostic latch), which is itself strong evidence they are
**bespoke DOA5U/engine SPU code** rather than unmodified Sony EDGE.
