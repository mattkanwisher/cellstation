# SPU kernel reverse-engineering — Dead or Alive 5 Ultimate

Two hot SPU kernels captured by rpcs3's SPUDisAsm. Analysis is over the disassembly
windows provided (k07: LS 0x4f8–0xdf4; k08: LS 0xa268–0xab64). Some callees
(0x290, 0x8398, 0xb0f8, 0xec0…) lie outside the window and are inferred from call sites.

---

## Kernel 7 — LS 0x4f8, hash 6uuRfteCdqW  (1.45% CPU, DMA GET, ~0% float)

### Headline: this is NOT the reverb process routine. Reverb identification is REFUTED.

The prior label ("mstream i3dl2 REVERB plugin process routine") does not survive contact
with the code. An I3DL2 reverb process loop is a dense wall of `fm/fma/fs/fnms` running
parallel comb + series all-pass filters over a delay line, reading and writing a circular
audio buffer with a running modulo index. **None of that is present.** In ~220 instructions
there is not a single `fma/fm/fs/fi/frest` — literally zero DSP float math and zero
delay-line addressing. What is present instead:

- A **byte-scan string tokenizer** (0x4f8–0x668).
- **Lock-line atomic synchronization**: `GETLLAR` / `PUTLLC` reserve-and-commit spinloops
  (0x670, 0xba4/0xbec, 0xca4/0xd1c, 0xd58), each followed by `rdch MFC_RdAtomicStat` and a
  retry branch.
- **Doubly-linked-list surgery** (0xaa0–0xae0) and an object-reset/free (0xae4–0xb20).
- A **lock-protected work-queue service loop** (0xb24 onward) that dequeues items and
  `PUT`s them back to main memory.
- **STOP-and-signal host callbacks** to the PPU: `stop 0x3f80` / `stop 0x3f81` (0x838, 0x848).

This is a **control-plane / synchronization routine**, not audio DSP. In the mstream/audio
middleware context the most likely role is the **SPU-side command dispatcher + voice/buffer
free-list allocator** for the streaming engine — i.e. the bookkeeping that *drives* the DSP
plugins, which is exactly the kind of code that gets mis-attributed to "the reverb" when you
only have a symbol near the reverb's LS region. The ~0% float and 1.45% cost (pure
control/DMA-wait overhead) are consistent with a dispatcher, not a filter.

### Readable C++ reconstruction (the load-bearing pieces)

```cpp
// ---- (A) 0x4f8-0x668 : find next delimiter byte in a 32-byte token, split on ' ' ----
// r7:r8 hold up to 32 chars; r22 is a target/terminator byte; state kept in LS globals.
int find_first_match(qword lo /*r8*/, qword hi /*r7*/, uint8_t want /*r3 derived*/) {
    // per-lane pairwise max then compare to the two halves, gather to a 32-bit hit mask
    uint32_t hits = (gather_byte_eq(hi, want) << 16) | gather_byte_eq(lo, want);
    int pos = clz(hits);                 // 0x528  first set bit == first matching column
    return (pos > 15) ? -1 : pos;        // 0x52c  clgti #0xf : not found in this word
}
// The extracted char (r18) is then tested: ceq vs r22 (terminator) and == 0x20 (space).
// Parser state variables live at fixed LS addresses and are rewritten with stqr:
//   0x120,0x130  token accumulators      0x160,0x170  cursor / carry
//   0x180,0x190  result slots            0x1c0,0x1d0  EA / handle    0x1e0  flags
// This is a classic space-delimited command/name tokenizer building a token on the stack
// (cbx/cbd/cwd + shufb inserts at sp+index).

// ---- (B) 0x670 & 0xba4/0xbec : acquire a lock via lock-line reservation (spinlock) ----
void lock_acquire(uint64_t ea, void* ls128 /*128-byte aligned scratch*/) {
    for (;;) {
        mfc_getllar(ls128, ea);                 // GETLLAR : read reservation line
        mfc_read_atomic_status();
        uint32_t w   = load_word(ls128);         // 0xbc8 rotqby to scalarise
        bool     busy = (w & 8);                 // 0xbd0 test lock bit
        uint32_t nw  = busy ? (w | 0x10)         // contended: set waiter bit
                            : ((w & ~8u) | 1);   // free: take it (clear busy, set owned)
        store_word(ls128, nw);                   // 0xbe4 shufb back into the line
        mfc_putllc(ls128, ea);                   // PUTLLC : conditional commit
        if (mfc_read_atomic_status() == 0) break;// success; else retry (0xbf4 brnz)
    }
}

// ---- (C) 0xaa0-0xae0 : unlink a node from a doubly linked list ----
void list_unlink(Node* self /*r3*/, Node* other /*r4*/) {
    if (self->next)            self->next->prev0 = nullptr;   // lqd 0(r3)/0x10(r3); stqd 0
    other->link_a = nullptr;                                  // stqd r5,0(r4)
    if (other->flag /*0x20*/)  other->owner_ptr->field = 0;   // lqd 0x30 -> rotqbyi -> store
    other->flag = nullptr;                                    // stqd r5,0x20(r4)
}

// ---- (D) 0xae4-0xb20 : release/reset an object (calls the unlink helper) ----
void obj_reset(Obj* o /*r80*/) {
    list_unlink(&o->node[0x3a0]);   // brsl 0xaa0
    o->field_0xc40 = 0;             // stqd 0
    o->field_0x7f0 = 0;
}

// ---- (E) 0xb24... : lock the shared queue, then dequeue/commit work items ----
// Big 0x260-byte frame with two 128-byte-aligned scratch lines (r8,r10).
// Loop body (0xc84-0xd30): GETLLAR the queue head, compute item index
//   (idx = byte @ node+0xc ; addr = base + idx*4), PUT the item out to main memory,
//   PUTLLC the updated head; retry on lost reservation. Terminates via stop 0x3f80.
```

### Plain English
- **DMA inputs:** small `GETLLAR` reads of shared lock/queue lines from main memory (128 B and
  0x80 B), plus 32-B `GET`s of a shared header (into LS 0x3ffe0 / 0x3fff0). No large audio buffer.
- **Operation:** parse a space-delimited command/name string held in registers; take a
  shared-memory spinlock with atomic reservations; walk/unlink doubly-linked lists; service a
  work queue by dequeuing items and `PUT`ting them back; call the PPU via `stop 0x3f80/0x3f81`.
- **Outputs:** mutated shared structures in main memory (queue head, list links, object fields)
  and parser-state globals in LS. No PCM audio is produced.

### Descriptive name
`spu_stream_cmd_dispatch_and_voice_alloc` — *SPU command dispatcher + lock-free free-list /
work-queue manager* (the audio engine's control routine, **not** the reverb DSP).

### Confidence & ambiguities
- **Very high** that this is control/sync code and **not** a reverb/DSP kernel (zero DSP float,
  presence of GETLLAR/PUTLLC atomics, list surgery, host STOP callbacks — dispositive).
- **Medium** on the exact product role. "Command dispatcher + voice/buffer allocator for the
  streaming audio engine" is the best fit for the mstream context, but the same primitives
  (tokenizer + spinlock + queue) would equally describe a generic SPU job/message dispatcher.
  I could not see the callees at 0x290 / 0x8398 / 0xec0 (outside the window) to confirm what the
  dequeued items *are*.
- The `stop 0x3f80/0x3f81` semantics are app-defined; I read them as PPU-side alloc/log/mutex
  thunks but cannot pin the exact syscall.

## Kernel 8 — LS 0xa268, hash iK5iWXc7oPu  (1.38% CPU, ~15% float, clean GET DMA)

### Headline: 4-wide (SoA) skeletal skinning + normal normalize + fixed-point vertex
### quantization, with a distance/LOD early-out. Bespoke (EDGE-*inspired*, not stock EDGE).

The kernel walks descriptor tables, DMAs vertex / index / matrix data with plain `GET`
(no atomics — matching "clean GET DMA"), transforms vectors by a loaded 4×4 matrix, renormalizes
directions with `frsqest`+Newton-Raphson, and packs the results to fixed-point integers with
`cflts`. That is a geometry/skinning + compression pass.

### Evidence for each stage
- **Descriptor / table indexing** (0xa268–0xa2f0, 0xa490–0xa4c0): loads a header at `r98+0x90`,
  extracts 16-bit indices (`and …,0xffff`), and computes record addresses with fixed strides
  `mpyui …,0xa0` (160-byte records) and `mpyui …,0x90` (144-byte records). These are
  bone / matrix-palette / mesh-part descriptors.
- **Type scan** (0xa304–0xa334): loop over 0x7e0-byte records, `ceqi r2,2`/`ceqi r2,3` — selects
  entries of type 2/3 (mesh-part or bone-group kinds).
- **Distance / LOD early-out** (0xa3e0–0xa488): `fs` two vec3s, dot via `fma` chain, `frsqest`+`fi`
  1/sqrt, compare `fcgt r2 > r9` and branch out (0xb0f8) — reject when the object is beyond a
  distance threshold (camera-distance LOD / culling).
- **4×4 matrix × vector transform** (0xa530–0xa638): loads a matrix from offsets 0/0x10/0x20/0x30,
  splats vector components (`shufb …,pattern`), and accumulates with `fm`/`fma`; the SoA byte
  patterns `00010203 / 04050607 / 08090a0b / 0c0d0e0f` are the standard transpose masks for
  processing **4 vertices at once**.
- **Normalize** (0xa6fc–0xa760, again 0xaa a8–0xab18): `frsqest`→`fi`→`fnms`/`fma` Newton step →
  unit-length direction/normal.
- **AABB / min-max** (0xa624–0xa6f0): paired `fs`(diff) + `fa`(sum) with `fcgt`+`selb` — building
  or updating a bounding interval.
- **Fixed-point quantize + pack** (0xa768–0xaa00 loop): `cflts …,0xad` (float→int with scale) on
  the transformed components, then a dense `shufb`/`roti` sequence that packs them into a compact
  vertex format; countdown loop `ai r86,-1 … brnz`. This is the per-vertex output writer.

### Readable C++ reconstruction (the load-bearing pieces)

```cpp
struct BoneRec  { /* 160 bytes (0xa0) */ float mtx[3][4]; /* +extras */ };
struct PartRec  { /* 144 bytes (0x90) */ };
struct GroupRec { /* 0x7e0 bytes; type field near +0x7d0 */ };

// ---- distance-based LOD reject (0xa3e0-0xa488) ----
bool lod_reject(const float3& a, const float3& b, float maxDist2) {
    float3 d = b - a;                       // fs r5
    float  q = d.x*d.x + d.y*d.y + d.z*d.z; // fma chain -> r114
    float  len = q * refine_rsqrt(q, frsqest(q)); // frsqest+fi+fnms+fma  -> distance
    return len > maxDist2;                  // fcgt r2,r9  -> brnz out
}

// ---- 4-wide SoA skin/transform (0xa530-0xa638) ----
void transform4(const float m[4][4], SoA4& v /*x,y,z in 3 quadwords*/, SoA4& out) {
    // splat each source component across a lane group, fma-accumulate the matrix rows
    out.x = m[0][0]*v.x; out.x = fma(m[1][0], v.y, out.x); out.x = fma(m[2][0], v.z, out.x);
    // …y,z similarly; produces 4 transformed vertices per pass (fa r62/r95/r87)
}

// ---- normalize (0xa6fc-0xa760) ----
float3 normalize3(float3 v) {
    float q  = dot(v,v);
    float rs = frsqest(q);
    rs = rs * (1.5f - 0.5f*q*rs*rs);        // fi/fnms/fma Newton-Raphson step
    return v * rs;
}

// ---- quantize + pack output (0xa768-0xaa00) ----
for (int i = count; i; --i) {                // ai r86,-1 ; brnz r86,0xa7b8
    int32_t xi = cflts(out.x, /*scale*/0xad);// float -> fixed-point
    int32_t yi = cflts(out.y, 0xad);
    int32_t zi = cflts(out.z, 0xad);
    packed_vertex = shuffle_pack(xi, yi, zi, …); // shufb/roti compaction
    store(dst, packed_vertex);
}
```

### Plain English
- **DMA inputs:** clean `GET`s (no atomics) of a descriptor header (`r98+0x90`), arrays of
  160-byte and 144-byte records (matrices / mesh parts), 0x7e0-byte group records, and per-vertex
  source data. Sizes/EAs are computed from 16-bit indices with strided multiplies.
- **Operation:** select records by type; do a camera-distance LOD reject; transform vertices by a
  4×4 matrix 4-at-a-time (SoA); renormalize normals/directions; compute a min/max bound; quantize
  the results to fixed-point and pack them into a compact vertex layout.
- **Outputs:** packed fixed-point transformed vertices written back to LS/main memory (the mesh
  ready for the RSX), plus updated bounds.

### Descriptive name
`spu_skin_transform_quantize_lod` — *SoA skeletal-skin / matrix transform with normal
renormalization, distance-LOD culling, and fixed-point vertex packing.*

### Stock EDGE vs bespoke
**Bespoke, EDGE-inspired — not stock SCE EDGE geometry.** It borrows EDGE's techniques
(4-wide SoA transpose masks, `cflts` fixed-point (de)compression, DMA-streamed vertex work) but:
- record strides are unusual (160 / 144 / 0x7e0 bytes) rather than EDGE's `EdgeGeomSpuContext`
  layout, and there is no EDGE command-buffer / `edgeGeom*` structure signature in the window;
- it carries an **inline distance-LOD reject** and custom minimax float constants
  (`-0.00126249f`, `-0.0501743f` at 0xa50c/0xa514, likely an angle/lighting polynomial) that stock
  EDGE skinning does not include;
- the assertion traps (`heqi lr,…,0`) are the title's own guards.
So: DOA5U's own vertex-processing job that reuses EDGE-style idioms.

### Confidence & ambiguities
- **High** that this is float geometry work: matrix transform + normalize + `cflts` quantize are
  unmistakable, and the "clean GET DMA / ~15% float" profile matches.
- **Medium-high** that the specific role is **skinning + vertex-compression output** (vs. a pure
  collision/contact pass). The distance test and type==2/3 scan admit a collision reading, but the
  matrix-palette indexing + SoA 4-vertex transform + fixed-point pack loop weigh clearly toward
  skinning/geometry with LOD culling.
- The exact meaning of the 144-byte vs 160-byte records, and the two small negative float
  constants (angle poly? light term?), are inferred; the callee at 0xb0f8 (taken on LOD reject) is
  outside the window.
